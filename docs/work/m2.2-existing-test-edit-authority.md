# M2.2 — existing-test edit authority (frozen before implementation)

Discovered by Family 3's E2 (`experiments/mutation-v2`): a governed change
whose plan responsibly edits its own *existing* test file beside a covered
production file reads `1 anchor over 2 planned files` and stays cold,
because every derivation family reads non-test files only. #312 opened this
for *new* test files (prospective CREATE authority). This is the sibling
seam for *existing* ones — an execution-authority seam found by a natural
run, not a fourth family.

## The distinction that must not blur

**Do not teach Sensei that an existing test file has architectural coverage
because its production sibling does.** Coverage is evidence about
architecture; a test edit is an operation. M2.2 adds a separate, bounded
**operational authority**, exactly as #312 did, and routing carries the two
kinds side by side:

```text
modfile/rule.go        architectural authority:  mutation confinement DERIVED
modfile/rule_test.go   operational authority:    existing regression-test edit grant
```

never `architectural coverage: 2/2`.

> The grant authorizes editing regression evidence. It does not establish
> that the test is sufficient, correct, relevant, or passing. Those remain
> the job of test execution, audit, and independent review.

## The predicate

```text
EXISTING_TEST_EDIT_ADMISSIBLE(F, S, W)   F existing test file, S covered subject, W pinned world

role: go-regression-test-edit

GRANT iff
  1. F is positively PRESENT at W, and its exact base blob hash is recorded on the grant
  2. F matches *_test.go
  3. F and S are in the same directory and declare the same Go package at W
  4. S is in the plan and holds mechanically established architectural coverage
     (a derived anchor over S at W)
  5. the operation on F is EDIT only: no create, delete, or rename
  6. F's package clause and build constraints (//go:build, // +build) may not change
  7. imports(F after) ⊆ imports(F @ W)   -- v1: no novel-dependency allowance at all
  8. the exact grant reaches the worker (implementation prompt), as in M2.1
  9. independent post-edit inspection checks the candidate's F against that exact grant;
     a mismatch is terminal (no retry, no reinterpretation), as in #312

otherwise UNRESOLVED -> F stays unauthorised; the plan routes as today
```

Facts read at W only (`git show W:F`), never from the working tree. The
grant is a durable receipt (recorded, restored on resume, matched one-to-one
against declarations), same lifecycle as prospective grants.

## Falsifiers, frozen — each must leave F unauthorised or refute the candidate

```text
foreign-package test      F declares a package other than S's (e.g. modfile_test vs modfile)  -> no grant
missing test              F absent at W (that is #312's case, not this one)                     -> no grant
uncovered sibling         S has no derived anchor at W                                          -> no grant
different directory       F in another directory than S                                          -> no grant
package change            candidate changes F's package clause                                   -> REFUTED
build-tag change          candidate adds/removes/changes a build constraint                      -> REFUTED
novel import              candidate imports something not in imports(F @ W)                     -> REFUTED
delete / rename           candidate removes F or moves it                                        -> REFUTED
unreadable F              git show fails for reasons other than absence                          -> UNRESOLVED, no grant
```

Positive: a candidate that edits F's body inside its existing imports, same
package, same constraints, beside a covered S -> admissible; then the plan
over {S, F} routes with S's architectural authority and F's operational
authority, and the implementor runs.

## What this is not

Not coverage for test files. Not a widening of the derivation families to
read tests. Not permission to add dependencies to a test (v1 has no
allowance; if a run shows one is needed, that is an architect decision with
a new role version, not a silent widening). Not sufficiency of the test.

## Proof plan

Unit falsifiers above; an engine-level test that the route with {S covered,
F granted} is granted and with {S covered, F ungranted} is cold; a resume
test that a restored grant matches its declaration or refuses. Then a fresh
frozen witness on `golang/mod` (E3, task text written from the code) to
observe: Family 3 anchor + test-edit grant -> implementor -> inspection ->
audit -> review -> execution consequence -> FULL FAMILY-3 GATE.
